### 2. 建立可扩展因子计算能力

- 完成文本／AST DSL、类型与参数校验、表达式规范化身份、组合展开及累计历史需求检查。
- 提供 60 个基础算子，包含 TS_PROD、TS_RANKCORR、TS_WINSORIZE。
- 支持运行内组合与 TS／CS group_batch 算子注册；基础算子使用 Polars，自定义代码通过子进程验证后使用本地 Numba 执行。
- 注册验证覆盖有效输出、因果性、合约／交易所／连续段隔离、截面成员约束、性能增长及超时等边界。
- 每个 fold 采用训练起点前一个自然年的预热数据；可用窗口与累计历史需求由实际数据推导，推荐窗口不再充当硬限制。

### 3. 打通统一实验与因子库流程

- 接通同步 SearchSession、顺序批量评价、尝试预算，以及现有 Random／GP／MCTS／Atlas 基线适配。
- 实现训练期方向确定、训练／验证 IC 与覆盖率评价、全库精确 Spearman 相关性去重及自动准入。
- 使用原子 trial JSON 保存试验、入库和成本证据，支持只读因子库查询与重建。
- 冻结保存因子定义、算子依赖和运行指纹，提供独立 OOS 入口和基础比较报告；旧格式不静默迁移。

### 4. 推进检查点恢复

最新源码新增 checkpoint.py、atlas resume 入口，以及四类 ask/tell 基线的方法状态序列化和恢复测试，涉及中断前后逻辑一致性、预算与库成员一致性、指纹不兼容拒绝、单写者锁和失败记录。

该能力晚于当前说明文档，文档中的“恢复尚未实现”需要按实际支持范围更新。现阶段范围是同一个同步 ask/tell 运行；普通 run(session) 插件不能自动恢复调用栈，不能据此宣称具备完整方法、LLM 请求或分布式任务恢复能力。

## 当前问题与研究限制

- 当前完整检查存在格式阻断，恢复能力的代码与文档状态需同步。
- 尚无正式多 seed 对比、当前版本真实 OOS 报告或稳健 alpha 结论；四类搜索器仍为最小基线，不能标为论文完整复现。
- LLM 工具与 token 预算、外层总活动时间监督、开放式 Atlas 搜索、跨频与学习型算子尚待实现。
- 数据获取完成不代表所有字段完整；基本面历史修订与未知日内缺 Bar 限制需持续披露。
- 自定义算子为可信本地代码执行，正式计算不能在内核内部强制中断，也没有硬性内存隔离。
