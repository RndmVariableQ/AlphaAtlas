# Analyst + Miner 长程基线

入口 `--method analyst_miner`。Research Analyst 根据本运行历史选择研究方向并制定计划；
Factor Miner 每个计划启动新对话，在计划内逐次接收平台反馈。没有 Explorer、Region 选择或
退火。Miner 和 Analyst 使用原有五个公共只读工具；Miner 查库不受对话重置影响。

Analyst 每轮收到公共 context 和结构化压缩的运行历史。历史包含总计划数、trial 数、入库数和
结果分类计数，以及最近最多 40 条计划和 40 条 trial 的简化记录；记录方向、假说、结束原因、
候选公式、Train/Val 主指标、覆盖、残差和重复信息等。更早的计划保留简短方向索引。长文本会标记
截断；历史部分限定在 120,000 字符以内，必要时从最早的方向索引起移除，并明确提供省略条数。
模型不能从方向索引和计数恢复更早的具体
失败经验；正式成员仍可通过公共库工具查询，原子 trial 是完整评估事实的权威来源。
无候选的阻塞计划同样保存。输入快照保存在当前计划状态，恢复时沿用并在发送前压缩；已保存的
查询和模型回复不会重发。此上限仅约束历史部分，不保证公共 context、工具查询和回复的总输入
不会超过服务限制。无新候选的连续阻塞有界。

Miner、字段校验、计划内停止、生成失败 trial、预算、准入和恢复复用既有方法和平台。候选
不带 Region。方法记录配置、计划、原子 trial 引用和模型用量；中断后已保存回复不重发。

该方法是自建系统基线，不是仅移除区域证据的消融。与 V3 async 的比较同时涉及角色分工、
信息组织和并发程度；应报告 token、调用、耗时及未知用量，不把差异单独归因于 Atlas。
真实结果记入实验记录，单次历史留出集比较不证明稳定优势。
