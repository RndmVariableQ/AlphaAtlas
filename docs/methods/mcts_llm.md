# MCTS-LLM 搜索适配

入口 `--method mcts_llm`，实现标识 `mcts_llm_atlas_v1`。
已有五维搜索算法、FSA、阶段恢复与模拟测试；真实运行见[实验记录](../records/experiments.md)。
遵循[方法复现规范](../method_reproduction.md)，与 `mcts` 符号基线独立，不声称复现论文收益。

## 1. 固定来源

- 目标论文：[Navigating the Alpha Jungle](https://arxiv.org/pdf/2505.11122v3)，
  arXiv:2505.11122v3，2025-11-12。采用第 3 节、附录 D/F/G/K 的机制定义。
- 用户指定的 [dtbtc 仓库](https://github.com/dtbtc/mcts-llm-alpha/tree/cab5d91f3cb834c3810811142407047bd2fef7ff)，
  `master` 核对提交 `cab5d91f3cb834c3810811142407047bd2fef7ff`。
  该仓库自述为第三方论文复现；本方案不将它认作作者官方实现。
- [MIT 许可证](https://github.com/dtbtc/mcts-llm-alpha/blob/cab5d91f3cb834c3810811142407047bd2fef7ff/LICENSE)。
  实际移植源码或提示词时保留许可证要求的声明。

论文固定为 v3，仓库可能依据较早论文或自行调整。下列“不一致”只指与当前目标版本
不一致，不推断原作者意图，也不把仓库 README 的效果陈述当成验证结果。

## 2. 使用哪些模块

下表上游文件均相对 `mcts-llm-alpha/src/mcts_llm_alpha/`。

| 上游模块 | 使用方式 | 本地归属 |
| --- | --- | --- |
| `mcts/node.py`、`mcts/search.py` | 参考公式节点、路径上下文、选择和改进阶段；按下节纠正差异 | 方法自己的树状态、ask/tell 与生成阶段 |
| `llm/prompts.py`、`llm/wrapper.py` | 参考画像→公式、定向改进和修复提示；替换字段、DSL、工具与评估说明 | 方法提示词；公共 context 提供研究事实 |
| `llm/example_selector.py` | 参考按改进维度选择成功示例的策略 | 从本次运行库查询，方法内排序 |
| `llm/overfitting_evaluator.py` | 参考基于公式和改进历史的风险判断 | 方法模型阶段；失败不能补固定分 |
| `evaluation/relative_ranking.py` | 参考排名转换思路，按论文明确方向和并列处理 | 方法纯数值奖励；输入仅为公共报告 |
| `mcts/fsa.py` | 保留参数抽象、支持度和闭合子树机制 | 遍历本地规范 AST；不照搬字符串包含判定 |
| `formula/validator.py`、`fixer.py`、`cleaner.py` | 仅参考纠错流程，不移植另一套表达式语义 | 本地编译器判合法，LLM 按真实错误修正 |
| `evaluation/qlib_evaluator.py`、`metrics/*`、`comprehensive.py` | 阅读指标意图，不直接调用；不带入数据、标签或准入 | 公共 evaluator 与 SearchSession |
| `llm/client.py`、缓存、CLI、pickle checkpoint、YAML 配置框架 | 不移植 | 复用现有模型客户端、runner、TOML、trial 和方法状态 |

搜索实现集中在 [mcts_llm.py](../../src/alpha_atlas/methods/mcts_llm.py) 与
[方法配置](../../configs/mcts_llm.toml)。工厂、CLI、冻结配置检查复用现有方法接入路径。
共享诊断位于 evaluation/session/reporting，方法不读取面板。编译预检复用
`SearchSession.validate_expression`：只返回规范 AST 和错误，不计评估尝试，不增加模型工具。

## 3. 论文与仓库差异及本地决定

论文公式位置见 [第 3 节及算法 1](https://arxiv.org/pdf/2505.11122v3)。
具体上游行为依据固定提交的
[树搜索](https://github.com/dtbtc/mcts-llm-alpha/blob/cab5d91f3cb834c3810811142407047bd2fef7ff/mcts-llm-alpha/src/mcts_llm_alpha/mcts/search.py)、
[节点](https://github.com/dtbtc/mcts-llm-alpha/blob/cab5d91f3cb834c3810811142407047bd2fef7ff/mcts-llm-alpha/src/mcts_llm_alpha/mcts/node.py)、
[排名](https://github.com/dtbtc/mcts-llm-alpha/blob/cab5d91f3cb834c3810811142407047bd2fef7ff/mcts-llm-alpha/src/mcts_llm_alpha/evaluation/relative_ranking.py)、
[FSA](https://github.com/dtbtc/mcts-llm-alpha/blob/cab5d91f3cb834c3810811142407047bd2fef7ff/mcts-llm-alpha/src/mcts_llm_alpha/mcts/fsa.py)。

| 项目 | 论文／上游情况 | 本地决定与验收依据 |
| --- | --- | --- |
| 节点和根 | 节点是完整公式；论文先评估根 | 根也必须提交一次公共评估，不能无分启动；测预算为 1 |
| UCT | 论文 Eq.2 为 `Q+c*sqrt(log(Np)/Nc)`；代码探索项含 2，并归一化 0–10 分 | 采用论文式及 0–1 奖励；手算选择，不能只搬 c 数值 |
| 虚拟动作 | 论文计数 `1+子节点数`；代码使用子节点数 | 采用论文计数；虚拟动作 Q 明确采用当前节点已知子树最大值，作为本地补充约定；测内部节点再次扩展 |
| 回传 | 论文和节点代码均使用子树最大分 | 保存固有分数与子树 Q 两个量；更新访问数及 max，不能复用本地符号 MCTS 的累计奖励 |
| 扩展约束 | 代码每维最多两次，并有低分终止／深度限制 | 不把这些额外启发式作为论文默认；保留全局尝试和公共 AST 复杂度规则 |
| 相对排名 | 论文 `e=1-比例(参照值严格更好)`；代码数严格更差的比例，并列分不同 | 按论文定义方向化后比较；`[0.1,0.2]` 中候选 `0.1` 得 0.5，测并列 |
| 冷启动 | 代码库小于 5 时使用硬编码绝对分档 | 不移植分档。空正式库时已定义的统计维度给中性先验 0.5，标明为本地启动约定；它不是原始测量值 |
| FSA 来源 | 论文基于有效库；代码在 `expand_node` 中把每个成功扩展公式送入 FSA | 仅按本次正式库新增成员更新；拒绝候选只留搜索历史 |
| FSA 闭合判断 | 代码使用字符串包含判断超树 | 在规范 AST 上核对结构包含与相同支持度；同一公式只计一次支持 |
| 库准入 | 仓库有冷启动放宽、多维门槛，论文附录与伪代码的检查时点也不同 | 一律由平台每次 evaluate 原子准入；是明确的平台适配，不能复刻上游动态放宽 |
| 动态预算 | 论文／仓库发现更好分数后增加局部搜索额度 | 保留树内机会分配，受全局 attempts 截断；局部结束再生成新根，测重启和尾部预算 |
| 评分失败 | 代码缺 LLM 或风险评分解析失败时可返回 5.0 | 明确失败并按阶段恢复，不记成功风险分，不触发虚假突破 |

以上取舍已经用于本地实现。未安装或运行上游依赖，不宣称上游测试通过。

## 4. 搜索流程与奖励映射

1. LLM 生成根假设与具体 DSL，runner 评估后建立根。参数枚举若实际测了 k 个候选，
   就提交 k 次 trial；主实现优先直接生成具体参数，不引入隐藏参数评估器。
2. 从根按 UCT 比较已有分支和虚拟动作，选出一个待改进公式。
3. 根据 `softmax((1-e)/T)` 采样薄弱维度，向 LLM 提供完整祖先路径及父／子／兄弟的改进记录、
   公共报告和合法 few-shot；先提改进建议，再转成具体公式。公式检查与修复沿用公共 DSL。
   在 ask 中依据候选公式和此时已有历史完成模型风险判断，保存响应后再提交候选；
   不依赖当前候选尚未发生的评估结果，不需要新增评估后模型调度机制。
4. 公共 evaluate 返回反馈；方法取得必要的共享诊断，并结合已保存的风险分数计算
   五维平均奖励。tell 只更新节点、路径访问和 max-Q，不调用外部模型。
5. 新入库成员参与后续排名、示例与 FSA；树局部额度内遇到严格突破时增加局部额度。
   全局额度到零后完成已提交候选的必要更新，再由平台冻结，不能继续生成候选。

五维奖励与最终平台成绩严格分开：

| 维度 | 输入与使用方式 | 本地实现 |
| --- | --- | --- |
| 有效性 | 公共 train 主指标，按训练方向后的质量；与正式库训练指标排名，越大越好 | 已实现；期货主指标由 profile 决定，不硬编码为论文 RankIC |
| 稳定性 | 公共训练期 ICIR 诊断，方向与主指标一致，再作相对排名 | 已实现；资产分组与边界见下节 |
| 换手 | 公共训练期持仓变化诊断，越小越好 | 已实现；A 股日排名持仓、期货原生 Bar 单位持仓，均为显式本地适配 |
| 多样性 | 与当前正式库的训练相关统计，取 `1-max(abs(corr))` 再排名 | 复用 factor_correlations；空库先验与有库但相关不可定义必须分开 |
| 过拟合风险 | LLM 根据公式及可见改进历史给出“低风险为高分”的 0–1 评分及理由 | 已实现独立风险阶段；不使用 test，不以 train-val 落差替代该机制 |

原始统计的数值定义归公共层，排名与五维平均归方法层；所有量的尺度与 T 同步固定。
既有 `TrialFeedback.max_abs_corr` 是准入用验证相关，不能当训练多样性直接复用。
不可定义的必要诊断使该候选无法获得完整搜索奖励，记录失败原因；不因缺一个维度
偷偷改成四维平均。空池先验只解决“没有参照对象”，不掩盖缺失测量。

排名采用候选评估前的正式库视图，排除自身；保存所用库版本和当次分数，后续不重写
旧节点的历史奖励。多样性参照值也保存其当时库语境，披露这是随库变化的历史评分。
公共准入仍按即时规则执行；保存评估前视图不延迟或绕过准入。
必要的训练相关对可在已有方法会话中请求；不新增模型数据权限。

共享训练诊断的定义与缺失规则见[数据与实验规范](../research_protocol.md#共享训练诊断)。

参考示例仅来自当前正式库，或公共开关允许的无绩效参考定义；两者身份明确区分。
FSA 保留参数抽象后的 root gene、按公式支持度和闭合结构 top-k 规避；只把它作为
本方法生成约束，不能变成所有方法的正式准入规则。规避检查使用 AST，失败后走有界
纠正阶段；原始及修复回复都计模型成本，提交的非法候选照常扣尝试。

## 6. 配置、运行与限制

模型、服务地址与密钥环境变量名见[方法配置](../../configs/mcts_llm.toml)。
服务需兼容 Chat Completions；密钥只从配置指定的环境变量读取。阶段温度随请求传递，
本地客户端省略 `max_tokens`，实际输出长度受服务限制；这是本地选择，原参考风险阶段设为 200。

| 配置／约定 | 当前值 | 来源／偏离 |
| --- | --- | --- |
| UCT c、维度 T | 1、1 | 论文 v3，奖励统一为 0–1 |
| 初始树扩展预算／突破增量 | 3／1 | 论文值；根另占一次全局评估 |
| 生成／公式修复／风险评分温度 | 1.0／0.8／0.1 | 论文附录 G；服务仍可能非确定 |
| FSA top-k | 3；0 关闭 | 论文默认，关闭用于消融 |
| few-shot | 最多 1 个 | 有效性／稳定性在低相关一半中择优；多样性选最低相关；换手／风险 zero-shot |
| 冷启动排名 | 0.5 | 本地先验；只针对有测量值但无可用参照分布的维度 |
| 空库原始多样性 | 1，排名先验仍为 0.5 | 无参照对象；有库但必要相关未知则为 null |
| 公式修复 | 最多 3 次 | 本地有界纠错；失败保留原非法 DSL，FSA 耗尽记录生成错误 |
| 每阶段对话 | 最多 8 轮，每轮最多 16 个只读查询 | 查询和格式纠正共用轮数；耗尽记一次生成失败 trial |
| 无树选择消融 | `tree_selection=false` | 当前树节点均匀选取，保留其余生成和反馈流程 |

排名只比较参照库中该维度已知的历史测量值；该维度没有已知参照时使用明确先验，
候选本身必要诊断缺失仍不产生奖励。节点内在分、子树 max-Q 和参照库版本分开保存。
同一 factor ID 不重复建点；失败／重复仍消耗全局尝试和当前树扩展机会，不伪造回传分数。
正式入库但搜索诊断不完整的候选保留成员身份并更新 FSA，不能把方法失败当成公共撤库。

```powershell
uv run atlas run --asset futures --fold fold1 --method mcts_llm --attempts 100
uv run atlas run --asset ashare --fold fold1 --method mcts_llm --attempts 100
uv run atlas resume artifacts/runs/<run_id>
uv run atlas report artifacts/runs/<run_id>
uv run atlas test artifacts/runs/<run_id>
```

请求所用的公共 context、阶段输入、原响应、查询结果、解析／编译反馈和阶段结果保存在
既有方法状态，供恢复；提示词来自执行时源码，阶段温度来自冻结配置。
公共重试、成本与恢复边界见[方法复现规范](../method_reproduction.md#预算失败与恢复)。
方法状态保存模型阶段、原始响应、查询结果和解析反馈；已保存响应即使尚未解析也不重发。
修改模型地址等冻结配置需新建运行。必要风险评分失败不补固定分。

机制消融至少区分完整适配、去 FSA、去树选择；去树选择应保留相同生成与反馈阶段。
现有 `react` 和 `mcts` 可作系统参照，不能代替这一受控消融。去掉任一关键维度或
以模板替代 LLM 的版本使用独立标识，不以完整 MCTS-LLM 名称报告。
冻结库可使用公共 [model 入口](../model.md) 训练 linear／LightGBM 并独立评估组合预测 IC；
它不改变本方法的搜索和奖励，也不宣称复现原论文组合成绩。原论文的 top-k、MLP 和
交易收益实验尚未接入。
