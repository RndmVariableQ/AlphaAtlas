## 一轮研究

1. Explorer 收到原退火流程的 breadth/depth、当前 Region、完整 run 内地图和已研究方向。
   地图沿用原配对主指标统计，支持／反向 trial 额外附完整候选与 Train/Valid 指标。
2. 必要时通过现有五个 SearchSession 只读工具查库，支持公共接口的关键词 AND、分页和
   run/reference 范围。`library_search` 与 `library_get` 的完整结果可引用；
   `library_list`、`library_stats` 只提供索引／统计，不能代替完整测量证据。
3. Explorer 一次提交一至三个完整方向，有一条即可。每条包含问题、机制假说、条件、可观测预测、竞争解释、
   引用，以及已有 Region 或现有 continent 下的新 Region。四项评分均为 1–5 整数并须
   给出理由：研究价值 30%、实验判别价值 30%、研究区别 20%、可执行性 20%。
4. 服务端计算百分制分数 `sum(score * weight) / 5`，选择最高项；并列保留提交顺序，
   不消耗退火 RNG。只有选中方向的新 Region 才注册。整批方向先全部校验通过，
   再交接选中项，避免格式修复留下部分 Region。
5. 原 Analyst 接收选中问题、完整 Proposal 及所引用的库证据，编写计划；Miner 按原流程
   逐条提交候选。Region reward、温度、接受概率、每计划候选数和准入全部沿用退火方法。
   四项选题评分只决定本轮研究哪个方向，不替代候选评估或 Region reward。

Explorer、Analyst、Miner 都能使用同一组五个公共只读查询工具；Analyst 与 Miner 的查询
使用 AlphaPROBE 的 `queries` JSON 批次格式，每轮最多 16 个请求、每阶段最多 8 轮。
Miner 的阶段指一个候选，计划字段和研究方向仍由上游约束；公共查询不改变这些权限。
查询与恢复的具体规则见 [annealing](annealing.md)，不开放额外评估或算子开发工具。

重复校验拦截仅改标题、其余研究内容相同的批内提案；机制是否实质不同仍依靠提示与研究审阅，
不宣称程序能判定自然语言语义等价。完整提案批次和被引用的库结果保存在原方法状态及本轮
最后一条 step 内；未选方向是本轮备选，不建立待执行队列或跨 run Proposal 数据库。
请求前按完全相同的 `(region_id, direction)` 去掉历史方向重复项，保留首次出现顺序；
不合并语义改写，不改地图统计、trial 或已保存的输入快照。

## 必须保留的本地差异

| 上游能力／规则 | V1 的本地处理 |
| --- | --- |
| `search_atlas` / `read_atlas` 的分页地图 | 保留完整 run 内精简地图注入；不新建公共工具 |
| 因子及所有状态的全局检索 | 复用公共正式库和配置启用的参考库；本 run 未入库证据来自已有 trial |
| `list_proposals` 与持久化待研究方向 | 输入本 run 已研究方向；保存一至三个提案，仅执行当轮选中项 |
| 来源 `kind/id/revision` | trial 使用原索引；库结果使用含研究轮次和请求位置的本地 ref 并保存原始内容 |
| 上游 1m 及大于 5m 的观察建议 | 使用本项目资产原生频率和显式频率 DSL；不改数据或预测期限 |
| 独立 Train/Valid 覆盖与服务端状态 | 保留本平台成功状态及 Valid 覆盖配对统计；不推测缺失 Train 覆盖 |
| 原始 Valid 需按 Train 符号翻转 | 本平台 Valid 已方向化，直接使用；不重复翻转 |
| 探索任务可提交不足报告后结束 | 保存 summary/unresolved；在剩余对话额度内澄清一次，仍无法提供任何方向则显式中止 |
| 外部客户端、存储和任务恢复 | 复用公共 HTTP、原方法检查点、原子 trial、冻结与恢复 |

日期、fold、universe、run/snapshot ID、标签与 OOS 不进入 Explorer 输入；
参考定义不携带当前绩效，不能免费准入。能力说明来自公共 context，不复制上游硬编码字段、
算子目录、供应商访问或预算策略。详见[方法复现规范](../method_reproduction.md)。

## 配置、失败与恢复

`configs/v1.toml` 沿用退火方法的模型、计划长度、温度和候选预算设置。
`max_dialogue_rounds` 默认 40，供 Explorer 的查询/修复和 Analyst 的对话修复分别使用；
Miner 仍使用 `max_formula_repairs`。Explorer 完成 20 次回复后，从第 21 次请求开始持续加入
收敛提醒：优先根据已有证据提交一至三个完整方向、评分和理由，仅为关键缺口继续查询；
证据不足时返回 `unresolved`，并重申使用 JSON 而非 DSML。提醒不是查询禁令，终端也显示
当前对话次数和提醒状态。第 40 次回复仍会校验、接受合格提案；未形成提案则停止，不再发第 41 次。

查询不扣候选预算，所有模型请求计成本。重复查询、非法引用、未知 Region、缺少评分理由或
空批次、超过三个方向均显式报错；对话耗尽仍使运行失败。提醒由已保存的回复数推导，恢复不重置轮数。
首次 `unresolved` 在现有对话额度内获得一次澄清：一条完整方向即可，不要求凑满三个。
再次 `unresolved` 或已无对话额度时仍停止，不伪造候选、不扣评估预算。
澄清复用原回复的错误反馈与对话记录；恢复旧的不足报告也能进入这一步，不重置请求计数。

每次请求前保存请求计数，响应保存后才处理，查询结果、修复原因、批次和选中项复用原检查点。
V1 独立校验方法状态版本与配置，旧退火运行沿用原入口恢复；不做检查点迁移。
新默认值不改写历史运行：冻结为 8 轮的旧 run 仍保留原限制，普通续跑不能直接切换为 40 轮。

```bash
uv run atlas run --asset futures --fold fold1 --method v1 --seed 42 --attempts 500
uv run atlas resume artifacts/runs/<run_id>
```
