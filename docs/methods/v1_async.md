# V1 异步研究

`v1_async` 在 [V1 Explorer](v1.md) 上增加持续异步调度，来源和 Explorer 同步范围见该文档。
这是 AlphaAtlas 的本地并发适配，不是 ChaoticTrader_Future 完整 pipeline 的复现。
旧 `v1` 和 `annealing` 的搜索机制、配置及恢复入口继续保留。

## 调度与职责

```text
Explorer：最新地图 → 一至三个提案 → 按评分选择空闲组所需的方向
                              ├─ Analyst A → Miner A ↔ 平台反馈
                              ├─ Analyst B → Miner B ↔ 平台反馈
                              └─ Analyst C → Miner C ↔ 平台反馈
某组完成 → 退火裁决 → 下一次 ask 用最新地图启动 Explorer 补位
其他组继续执行，不等待整批完成
```

- `parallel_plans` 控制并行研究组数，默认 3；每组内保持 Analyst → Miner 的顺序。
  各 Miner 只接收本组计划和本组逐次评估，反馈后才能生成本组下一候选。
- 最多一个 Explorer 请求链。每次提交一至三个完整且实质不同的提案，按原 30/30/20/20 评分排序，
  取空位和预算允许的前若干项；未选提案不排队。Explorer 可与其他组同时调用模型。
  一条完整提案也可用于补位，按实际批次长度排序和创建研究组；剩余空位后续继续补充。
  输入列出正在研究的提案，服务端拒绝机制、条件、预测和竞争解释均重复的方向；
  同一 Region 允许研究不同方向。这是结构重复检查，不声称能识别所有语义改写。
- 新 Explorer 在 runner 更新地图之后启动，其输入保存为该次探索的快照。
  进行中的研究保留自己的方向和计划。新 Analyst 的历史反馈来自最近完成的计划，
  沿用原有效覆盖、已入库和主验证指标 Top-K 筛选，并保存该反馈快照。
- 后台线程只发不可变消息副本对应的一次 HTTP 请求，不访问 SearchSession、地图或检查点。
  主线程接收回复，复用 V1 的查询、评分、修复、字段校验和 Miner 对话流程。
  已完成组先推进；同一次调度看到多个可提交候选时，按研究组创建顺序提交。
- runner 仍逐个 `evaluate → tell → atlas.observe`。评估、去重、入库和原子 trial 都是单写入者，
  模型 I/O 可以在评估期间继续。没有引入第二套工具、任务队列或结果账本。

三个角色都能使用五个公共只读查询工具，具体查询协议和上限见 [V1](v1.md)。
Analyst 和 Miner 的查询由协调线程执行并保存，后台模型线程不访问 SearchSession。

## 预算、退火与可比性

配置位于 [v1_async.toml](../../configs/v1_async.toml)。`candidates_per_plan` 默认 5。
调度前从剩余尝试数扣除活动计划尚未使用的额度；新空位按可用额度均分，每组不超过配置上限。
Explorer 进行中的额度也已预留，预算尾部可缩短计划，避免额外生成无法评估的候选。
只有 runner 的实际提交消耗公共预算，非法、重复和拒绝沿用平台规则。

Region 的累计入库率奖励和 Metropolis 公式不变；每个提案批次在启动 Explorer 时固定温度，
计划结束时按实际完成顺序更新共享 Region 得分和当前 Region。结束一个计划即可补位。
模型返回时序会影响候选提交、去重和退火次序，因此同 seed 不保证重现原串行轨迹，
也不保证两次新异步运行得到同一轨迹。比较实验需固定并发数并披露此差异。

## 失败与恢复

对话上限及收敛提醒沿用 [V1](v1.md)：默认最多 40 轮，Explorer 从第 21 次请求开始持续提醒
优先提交方向，仍允许必要查询；第 40 次合格回复正常接受。每次补位探索单独计数，
并使用该 Explorer 已保存的回复数恢复提醒，不影响其他组进度。
旧检查点中已保存的 `unresolved` 也按 V1 的规则在剩余额度内澄清一次；
已有研究组、计划、配额和原子 trial 保留，明确没有可执行方向时仍显式停止。

复用原 JSON 方法检查点，保存各组的方向、计划、回复、Miner 对话、额度、待提交候选，
以及 Explorer 状态、全局 RNG、退火状态和唯一待反馈候选所属组。Future 和线程不持久化。
已保存回复不重发，已提交 trial 复用原反馈；请求已发但回复尚未写入检查点时，恢复可能重发，
原请求用量保留 unknown。HTTP 408/429/500/502/503/504、连接失败等沿用公共客户端的重试分类，
由主线程执行最多 3 次额外重试和 1/2/4 秒退避，等待期间其他组可继续推进。
HTTP 200 但没有文本的代理响应，以及响应体内明确的服务过载，沿用相同重试和请求计数。
这些重试不生成 trial、不消耗候选预算；输出额度截断、拒绝和意外工具调用仍显式失败。

Explorer/Analyst 耗尽修复或模型硬错误显式终止运行；Miner 格式/表达式修复耗尽仍提交生成失败
候选并扣一次尝试。退出会取消尚未开始的请求；已经在网络中的请求受 HTTP 超时约束，
可能延后结束，但不会再写入研究状态。异步请求不逐 token 输出，避免并发回复污染终端。

并发配置纳入原冻结校验。旧串行 run 使用原方法续跑；启动异步实验需新建 run。
`generation_seconds` 是 runner 等待下一个候选的墙钟耗时，包含并发重叠，不能视为单请求延迟。
实际请求及已知 token 仍逐次累计；加速幅度取决于模型服务吞吐、限流与评估耗时。

## 运行与验证

```bash
uv run --env-file /home/ziyi/AlphaAtlas/.env atlas run \
  --asset futures_kernel_5m_full --universe all --fold fold1 \
  --method v1_async --seed 42 --attempts 1000
```

该命令与完整字段 AlphaPROBE 使用相同的 Kernel 复权 5m 资产、fold 和 seed；
新运行默认开放当前快照全部可用特征，不需单独添加 `--fields`。
模型、服务和凭据环境变量名由方法配置控制，切换后新建运行；恢复时须匹配原运行的冻结配置。

配置只保存凭据环境变量名；上面的启动命令加载本项目 `.env`，不将凭据写入运行产物。
测试使用合成数据、模拟回复和线程屏障，验证 Analyst 重叠、慢组期间补位、反馈隔离、预算尾部、
单线程写状态、重试计费、阶段中断、未完成请求恢复、原子 trial 恢复和配置冻结。
真实服务吞吐与市场表现需要独立实验，不由这些测试推断。
