# 待对比方法清单

更新日期：2026-09-12。本文整理外部候选方法与本项目已有实现，说明主要思路、
当前完成程度及对比价值；不表示这些方法已经完成统一实验或论文复现。

AlphaAgent 暂按 Tang 等人的因子挖掘论文版本理解。外部项目依据下列论文与仓库说明整理，
本项目状态依据当前工作区代码；后续正式实验应固定具体代码版本和配置。

所有方法统一遵循 [方法复现与比较规范](method_reproduction.md)：数据、DSL、指标计算、
准入、预算和冻结共用平台；搜索控制、方法奖励和提示策略保留各自机制。
规范覆盖本页全部方法，状态不会因文档接入自动升级。

## 一、总览

| 方法 | 核心思路 | 本项目当前状态 |
| --- | --- | --- |

| MCTS-LLM（论文／dtbtc 参考） | 用树搜索选择改进方向，由 LLM 改写因子公式 | 已有五维算法适配，`mcts_llm`；与本地 `mcts` 分开 |

## 二、外部候选方法

### 1. AlphaAgent

**主要思路：**用 Idea Agent 提出市场假设，Factor Agent 将假设转成因子，
Eval Agent 评估并反馈，形成迭代闭环。生成过程加入三类正则：以 AST 相似度约束重复，
检查假设与公式的语义一致性，并控制表达式结构复杂度，以减少同质化和过拟合。
来源：[论文](https://arxiv.org/abs/2502.16789)、
[论文代码分支](https://github.com/RndmVariableQ/AlphaAgent/tree/legacy-main)。

**对比价值：**考察“先提出机制假设，再约束生成”的策略，能否提升有效且非冗余的因子产出。

**当前边界：**本项目尚未接入。上述仓库的 `legacy-main` 明确对应论文，默认 `main`
现为另一套 A 股多因子研究框架，正式选型时应固定论文分支的提交版本，避免同名混用。
参见[当前主分支说明](https://github.com/RndmVariableQ/AlphaAgent)。

### 2. MCTS-LLM（论文／dtbtc/mcts-llm-alpha 参考）

**主要思路：**先由 LLM 生成因子画像，再转成符号公式并选择参数；随后以 UCT 选择树节点，
由 LLM 针对质量维度改写公式，评估后回传奖励。仓库描述的维度包括有效性、稳定性、换手、
多样性和过拟合，并使用相对排名、成功案例提示和允许内部节点继续扩展的虚拟动作，
通过频繁子树规避（FSA）引导结构多样性。
来源：[论文 v3](https://arxiv.org/pdf/2505.11122v3)、
[用户指定仓库固定提交](https://github.com/dtbtc/mcts-llm-alpha/tree/cab5d91f3cb834c3810811142407047bd2fef7ff)。

**对比价值：**考察树结构保存探索路径、分配改进机会的能力，以及 LLM 改写的额外贡献。

**当前边界：**该仓库自述为论文复现，不能据此认定复现质量已验证；本项目已接入
`mcts_llm_atlas_v1`，使用合成数据和模拟模型验证。
本地 `mcts` 只在固定文法中做符号搜索，没有上述 LLM 生成与多维改进机制。
完整规划见 [MCTS-LLM 复现方案](mcts_llm.md)。默认以论文 v3 定义算法，dtbtc 仅作
第三方实现参考；已核对虚拟动作计数、排名并列、FSA 来源与闭合判定等差异。
保留树搜索、五维奖励和 FSA，替换上游数据／Qlib 评估／正式准入／持久化。
公共稳定性和持仓换手诊断已实现，向所有方法一致开放；期货原生 Bar 持仓映射是明确
披露的资产适配。支持独立 `mcts_llm` 入口、阶段恢复、用量记录及 FSA／树选择消融。
尚未验证真实模型的市场效果，未复现原论文组合收益；不能直接拿上游回测结果当本项目成绩。

### 3. CogAlpha

**主要思路：**把因子表示为代码，使用七层 Agent 体系生成候选，质量检查 Agent
负责代码审查、修复与逻辑改进，再通过 LLM 变异和交叉推动演化；历史成功与失败反馈
用于指导后续生成。来源：
[CogAlpha_Prompt](https://github.com/uwFengyuan/CogAlpha_Prompt)。

**对比价值：**考察代码层面的搜索空间及多角色检查，能否发现固定公式模板难以表达的信号。

**当前边界：**用户提供的仓库明确只公开提示词，不包含运行代码、数据或实验结果。
因此应列为“依据公开提示词待实现”，不能列成可直接运行的完整开源方法。
若在本项目落地，需明确代码如何映射到现有 DSL／受限算子协议，以及哪些原方法能力被保留。

## 三、本项目已有方法与半成品

### 4. Random：随机搜索

**主要思路：**从算子、两个字段、窗口和字段组合方式中独立随机抽样，构造候选。
评估反馈不改变后续采样分布，用于衡量其他搜索策略相对于随机探索的增益。

**当前实现：**`RandomSearch`，入口 `--method random`。已具备运行与随机状态恢复能力。
它是可用的最小对照，但只覆盖有限模板，不代表整个 DSL 空间的均匀随机搜索。
代码：[baselines.py](../src/alpha_atlas/methods/baselines.py)。

### 5. GP：固定模板遗传搜索

**主要思路：**将候选编码为“算子、字段 A、字段 B、窗口、组合方式”的基因组。
初期随机生成；积累候选后用锦标赛选择父代，逐位置交叉，再随机变异一个位置。
评估后保留高奖励候选，默认种群容量为 32。

**当前实现：**`GeneticSearch`，入口 `--method gp`，已支持种群和待反馈状态恢复。
这是固定模板上的遗传基线，尚无任意深度程序树生成与一般子树交叉，不能当作完整树式 GP。
代码：[baselines.py](../src/alpha_atlas/methods/baselines.py)。

**对比价值：**验证对优良局部结构的保留与组合，是否比独立随机采样更节省尝试预算。

### 6. UCT MCTS：纯符号树搜索

**主要思路：**把同一基因组的各组成部分作为树的逐层决策。已有分支按 UCB 选择，
遇到未探索动作时扩展一个节点，其余部分随机补全；评估后沿路径更新访问次数和累计奖励。

**当前实现：**`MCTSSearch`，入口 `--method mcts`，单次提出一个候选，支持树状态恢复。
已有标准的选择、扩展、随机 rollout 和回传流程；搜索空间仍是固定模板，未接入 LLM。
代码：[baselines.py](../src/alpha_atlas/methods/baselines.py)。

**对比价值：**提供不使用 LLM 的树搜索对照，后续可用于分析外部 MCTS-LLM 的改进来自哪里。

### 7. Alpha Atlas：区域导航原型

**主要思路：**完整设想是将语义、实现与行为证据关联到研究区域，记录已探索方向、
失败证据和未解决问题，再据此决定下一步研究，而不只是给已有因子分类。
设计见 [Alpha Atlas 逻辑框架](alpha_atlas.md)。

**当前实现：**`AtlasSearch`，入口 `--method atlas`。目前仅以五类算子作为区域，
按区域平均奖励加 UCB 探索项选择区域，再在该区域内随机选择字段、窗口和组合方式。
它能更新区域访问次数和累计奖励，但还没有开放式假设生成、语义 embedding、
语义／实现／行为联合导航或自动生成新区域。
代码：[baselines.py](../src/alpha_atlas/methods/baselines.py)。

**对比价值：**当前可检验粗粒度区域预算分配；完整地图方法需继续实现后单独标识，
不能将原型的存在等同于完整设计已经落地。

### 8. AlphaPROBE：演化图检索适配

**主要思路：**维护因子的演化 DAG 与活跃父因子池。检索先验结合训练质量、深度和访问惩罚；
叶节点侧重数值、语义和 AST 结构多样性，非叶节点侧重子代质量增益与相关性。
选出父节点后，Analyst 结合祖先路径提出修改策略，Execution 生成 DSL，Validator 检查修正。
平台统一执行评估，结果继续更新演化图。

**当前实现：**`AlphaProbeSearch`，入口 `--method alphaprobe`，实现标识为
`alphaprobe_atlas_v1`。已有 Chat／embedding 调用接口、图检索、三阶段生成、只读查询、
方法状态恢复与成本记录；自动测试使用合成数据和模拟模型。
代码：[alphaprobe.py](../src/alpha_atlas/methods/alphaprobe.py)，
算法来源、具体公式与验证边界见 [AlphaPROBE 适配说明](alphaprobe.md)。

**适配边界：**本地质量采用绝对 train 主指标 IC，替代原文训练 ICIR；图内候选与正式因子库
分开管理，val 拒绝不删除训练搜索历史。尚未验证真实模型搜索效果，默认 embedding 模型
仍待配置；没有复现原论文动态组合和收益实验。

**对比价值：**考察祖先路径、多样性和历史改进潜力，是否能提高父因子选择与后续改写效率。

### 9. 单 Agent ReAct：反馈驱动搜索原型

**主要思路：**由一个 LLM 自行提出假设和公式，通过 JSON 工具请求查询规则、查看因子库、
提交评估，再依据反馈继续迭代。保留对话作为工作记忆；模型服务明确报告上下文超限时，
才摘要较早的完整交互轮次，并保留近期记录继续搜索。

**当前实现：**已有 `ReactSearch`、配置、候选生成／反馈、查询、摘要、检查点和用量统计代码。
CLI、Runner 与方法工厂已接入 `react`，入口为 `--method react`。
该实现仍在工作区完善中，本文暂列为初版，不将代码接入视为专项测试或真实模型实验已通过。
代码：[react.py](../src/alpha_atlas/methods/react.py)、
[方法工厂](../src/alpha_atlas/methods/__init__.py)。

**对比价值：**作为直接使用 LLM 与评估反馈的参照，用于检验多角色分工、树搜索、
图检索或地图导航是否带来额外收益。当前原型没有演化图检索或自定义算子注册工具。

## 四、统一对比时需要明确的口径

完整规则以 [方法复现与统一比较规范](method_reproduction.md) 为准，
其中模块归属、来源优先级、预算、奖励权限、参考库与验收要求适用于本页全部方法。

四个本地基线共用五类算子 `return/delta/mean/std/zscore`，字段组合为
`single/add/sub/mul/div`；5m 窗口取 3、6、12、24、48、96，其他频率取
5、10、20、60、120。这些是基线自己的采样策略，平台没有窗口或累计历史上限。
GP、MCTS、Atlas 当前共用“是否入库 + 非负验证主指标”的奖励；Random 不利用奖励。

正式对比需固定数据快照、资产与频率、目标、fold、字段权限、评估／准入规则和尝试预算，
并为每个方法、seed、run 保留独立因子库与方法状态。搜索仅使用允许的 train/val 反馈；
OOS 在冻结后评估，不能回流选因子。平台内部 SearchContext 保留预算用于停止控制；
模型可见 get_context 由 SearchSession 统一提供资产、频率、目标、主指标、字段、完整
算子、表达式／评估规则与参考库设置，不含预算、日期、fold、universe 或运行身份。
remaining_attempts 只出现在评估结果中。

主要比较有效非冗余因子的积累曲线、重复／非法／拒绝比例、单位入库增量成本，
以及冻结因子库的 OOS IC。LLM 方法还需披露实际模型、请求与 token 用量、耗时和初始化成本。
固定模板、完整 DSL 与代码生成具有不同搜索空间，统一评估器并不意味着严格控制了所有变量；
原论文收益、平台适配结果与本地最小基线结果应分别标注。

统一原始指标和最终成绩，不强制统一方法内部奖励；所有奖励只能使用公共允许的反馈。
初始化和参数试探均计入全局尝试预算，局部树预算增长不能增加全局额度。
现有默认模型与搜索空间尚未对齐，正式实验需先冻结同组条件；仅跑通相同 evaluator
不能宣称完成受控比较。已有方法的具体保留项和验收缺口见统一规范第 7 节。
