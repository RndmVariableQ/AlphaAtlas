# 数据与实验规范

本文集中说明数据、划分和数值评估规则。方法权限、预算、公平比较与复现要求见
[方法复现规范](method_reproduction.md)，表达式语义见 [DSL](dsl.md)。
参数以运行保存的配置为准，历史产物不随默认值更新而改写。

## 数据

| 资产 | 数据来源 | 研究范围 |
| --- | --- | --- |
| A 股 | RiceQuant 原生日线、PIT 财务与复权事件 | HS300、ZZ500、ZZ1000 的历史逐日并集 |
| 期货 | RiceQuant 原生 5m、rule=0 主力映射 | 主力对应的真实合约及日期 |
| 期货 Kernel 派生数据 | 用户指定的 Research Kernel 复权 1m 聚合为 5m | 主力真实合约；独立快照 |

- 默认请求区间为 2015-01-01 至 2026-09-01，含端点。时区为 Asia/Shanghai，Bar 标记结束时刻；
  期货交易日使用供应商 `trading_date`。非交易日不制造 Bar。
- A 股成员按历史当日确定；保留入选前数据用于预热，仅当日成员参与评价。退市记录保留，
  ST／停牌观测保留并排除评分。`union1800` 不表示整个历史只有 1800 个证券。
- `open/high/low/close` 为未复权价格；A 股的 `adj_*` 只使用截至当日生效的累计复权事件。
  每日 PIT 指标延后一交易日，保存来源日期；财报保留历史版本、公告／生效时间与修订标记。
  供应商入库时间不等于公告时间，历史修订限制见[数据验收记录](records/data.md)。
- 期货不以 1m 重采样替代原生 5m，也不以合成连续价格替代真实合约。行情身份是
  `(exchange, instrument_id)`；当前 profile 的因子窗口按 `(exchange, product)` 延续主力换约，
  并在已知缺日、无效行情和停牌处重置。目标仍在真实合约与连续段内计算。`close` 保持未复权，
  因此跨换月的价格窗口会包含合约价差跳变；当前仅获取主力对应日期，未补非主力期间预热。
  数据与其他项目独立。
- `.parq` 文件存于 `data/`，不入 Git。仅资产适配／导出层读取供应商或 Parquet，研究使用
  `MarketData`。空值保留，异常 OHLC 行保留位置、数值输入置空并排除评分。
- `manifest.json` 记录来源、实际覆盖、分区与缺失；`audit.json` 记录完整性审计。
  不完整采集不能标为完成，`--allow-incomplete` 仅供明确标注的诊断。

Research Kernel 完整字段资产为 `futures_kernel_5m_full`，聚合和字段见[数据记录](records/data.md)。
原 `futures_kernel_5m` 保留其四字段快照，既有运行继续沿用原配置、字段和数据身份。
MarketData 和完整性审计优先检查原始 OHLC；仅有完整复权 OHLC 时，按相同有限性和价格区间规则检查，
异常观测保留位置、数值输入置空并排除评分。

Kernel 导出按源 `received_at`、`ingest_seq` 取最新 `final` 版本，没有保留当时可见版本链。
其主力标记与累计复权因子的生效时间不能仅凭本地导出独立认证。固定快照上的前缀不变性
和无前视计算，不等价于供应商数据的完整历史版本 PIT；审计通过也不代表这项认证。
Zookeeper 固定目录将该限制保留为历史诊断 baseline，见其[说明](../src/alpha_atlas/factor_libraries/zookeeper/README.md)。

字段与来源配置见 [assets/](../configs/assets) 和 [fundamentals.toml](../configs/fundamentals.toml)；
远月腿与高周期规则见 [DSL](dsl.md)。

新运行默认使用 `MarketData.get_fields()` 从快照 schema 读取的全部可用数值特征，包括行情、
复权价格、已导出的远月行情及 PIT 基本面。不按字段的实际值或覆盖率筛选；身份、成员资格、
质量计数、复权因子等元数据以及 label/target 不进入默认输入。`--fields` 可显式缩小范围，
目标价格字段仍保留。实际字段列表在搜索前写入 run 配置并参与冻结；恢复沿用原列表，不重新扩展。

## 统一评估与准入

| 项目 | A 股 | 期货 |
| --- | --- | --- |
| 标签 | 未来 5 个日 Bar 的收盘对数收益 | 未来 12 个基础 5m Bar 的收盘对数收益 |
| 主指标 | 逐日横截面 Spearman IC 等权平均 | 品种 SQRT 成交额加权 Pearson IC |
| 质量门槛 | 定向 val IC ≥ 0.01 | 定向 train、val IC 各自严格 > 0.005 |

方向只由训练集主指标确定，val/test 沿用。期货标签可跨正常休市，12 根 Bar 不保证相隔
恰好 60 分钟。上述标签是研究目标，不代表可执行交易收益。

所有方法在计算 Pearson、Spearman IC 与 train ICIR 前，统一裁剪因子值和标签。
分位配置见 `benchmark.toml` 的 `clip_quantiles`，默认 1%–99%，采用线性插值。
每个因子在当前 fold 的 train 有效评分行上拟合一组因子边界；标签边界独立拟合，
不随因子缺失改变。两列各自使用有限值，跨日期、品种合并拟合，不含预热、非 eligible、
无效标签或标签终点越过 train 的行；指标仍按下述日期／品种口径汇总。
train、val 和 OOS 均使用这组 train 边界，不在 val／OOS 重新估计。
NaN／Inf／null 保持缺失，不通过裁剪制造有限值；无可用训练边界时评分值为 null，
不以 val／OOS 补估。常量边界保留常量，未定义指标沿用原拒绝规则。

边界保存在每个原子 trial 的评估报告中，并随入库因子冻结；OOS 只读取冻结边界。
训练因子相关性和验证库去重使用裁剪后的因子值，覆盖率仍按原始有限因子值计算。
换手诊断使用原始因子值，不受标签或评分裁剪影响。配置进入已有运行与冻结校验，
恢复复用已提交反馈，缓存缺失时只按需重建。历史产物保留，不为旧运行补写边界或混用指标。
配置中没有 `clip_quantiles` 的运行沿用未裁剪口径，恢复与 OOS 均不拟合或应用裁剪边界；
恢复前仍须将当前配置还原为运行保存值，不能在同一运行中切换裁剪策略。

期货先合并同品种各合约的评分样本，分别计算 Pearson 和重新排名的 Spearman，均报告
品种等权与 SQRT 成交额加权结果。权重为当前 split 内 eligible 行有限非负成交额之和的
平方根，不随因子缺失改变；品种有效样本少于 5 或指标未定义时不参与对应汇总，零成交额
不参与加权。没有有效分母返回 null，样本数只计实际参与部分。不同资产的 IC 不直接比较。

两类资产均要求 val 有效覆盖率 ≥ 0.8；在共同有效行上，与每个已有成员的绝对 Spearman
相关性须 < 0.7，至少重叠 100 行。不足重叠不视为非冗余，先入库者保留。
门槛见 [benchmark.toml](../configs/benchmark.toml) 和资产配置。

每个 `(asset, dataset, universe, fold, method, seed, run_id)` 独立维护因子库与地图。
主报告关注有效非冗余因子积累、单位增量成本与冻结库的 OOS IC；语义区域的新增不直接
计作有效发现。参考库定义仍须评估与准入，不能把定义数当作有效因子数。
模型评估另见 [model](model.md)；项目没有交易／下单接口。

## 共享训练诊断

当前新运行的共享诊断定义为 `icir_turnover_lag1_v2`，保留原 `icir_turnover_v1` 支持。
开关位于 `benchmark.toml` 的 `search_diagnostics`，空字符串对所有方法关闭。
MCTS-LLM 和 AlphaAtlas Agent 方法要求开启任一版本；AlphaSchema 要求 v2，
缺少必要诊断时在加载数据前报错。旧运行恢复／OOS 仍须还原运行保存的配置。
诊断保存在 `EvaluationReport.diagnostics`，经统一评估结果、库查询和 Markdown
报告提供；原有 metrics 顺序、训练方向、准入与 OOS IC 定义不变。

- ICIR：仅取 train 的 eligible／有效 target 评分行，先应用上述 train 裁剪边界，
  每组至少 5 对有限值。A 股先算日
  截面主指标；期货先算每个 product／trading_day 内的主相关，再按该 profile 的等权或
  固定训练期成交额权重汇总为日序列。至少两个有效交易日，以方向统一后的日均值除以
  样本标准差（ddof=1）；std ≤ 1e-12 或不足两个有效日返回 null，不补造“稳定高分”。
  期货按日切块是稳定性诊断，不改写主指标原有整段品种聚合。
- A 股换手：train 内当日 PIT eligible 成员的因子截面平均秩减去平均秩，再除以绝对值
  总和，得到 gross=1 的多空持仓；完全同秩时持仓为零。相邻完整观测日，对成员并集
  求 `0.5 * sum(abs(w_t-w_prev))`，再等权平均；新进／退出的另一侧权重为零。要求
  每个截面至少 5 个成员且值全部有限；不跨越无效日。第一日建仓不计入。
- 期货换手：每根原生 Bar 以 `sign(value)` 作为单位名义持仓，按因子 panel 的连续段计算
  相邻观测的 `0.5 * abs(position_t-position_prev)`；product panel 会跨主力换约，contract panel
  按真实合约隔离。使用远月字段的窗口仍按该腿实际合约切换分段。之后先按品种平均，
  再按 profile 等权／固定训练权重汇总。首笔、合约切换、已知连续段中断及 null 两侧
  不产生转移，不能跨过去拼接。单位标明为 `native_bar_unit_position`，不是日换手。
- 换手不读取未来收益，只使用 train 内特征有效行。它衡量固定持仓映射的变化，
  不包含交易费、滑点、实际成交约束或首笔建仓费用，不能当真实交易成本。
  这一持仓映射是本地诊断定义，不代表实际交易组合。

所有诊断是有限标量及计数，日期明细、持仓／标签数组不提供给方法。数值回归验证诊断
开启前后原有 IC 不变、修改 val 不改变 train 诊断、缺失与合约切换不制造换手。
训练相关使用既有有界缓存，丢失时只重建请求因子。

v2 在上述 ICIR／换手外增加原符号训练 `rank_ic`、`rank_icir`、`lag1_rank_ic`、
`lag1_gap=max(0,rank_ic-lag1_rank_ic)` 及计数。新增指标不使用训练方向翻转。
RankIC 沿用资产的日期／品种汇总和权重；RankICIR 将上述日 ICIR 的相关类型改为
Spearman，至少两个有效日且标准差大于 `1e-12`。两者在期货上分别是整段品种聚合和
逐日稳定性诊断，不混为同一口径。

lag1 先在完整 train 观测时钟上，将因子值按配置的 panel／连续段滞后一根原生输入 Bar，
再筛选 eligible、有效目标及 split 边界。前一 Bar 不 eligible 或因子缺失时不跳过拼接；
A 股额外要求市场观测日相邻，缺行不能跨日连接。train 第一笔不从预热取滞后信号。
product panel 可跨主力换约，已知 product 缺口重置；contract panel 按实际合约和连续段重置。
目标仍使用同一实际合约及目标边界。滞后与未滞后都应用原因子冻结的 train 裁剪边界，
不为滞后信号重拟合；二者各自使用有效配对样本并记录滞后样本数，不能解释为同样本
因果效应。没有足够有效配对时为 null。v2 通过现有评估身份区分缓存，不改写 v1 记录。

## 新资产实验前检查清单

新增资产或更换数据快照后，在正式搜索前逐项核对；实际字段、日期和参数以配置及运行产物为准。

- [ ] **数据与资产池**：来源、频率、时区、交易日、资产身份、历史成员资格明确；
  覆盖完整，缺失和异常有审计。
- [ ] **字段与单位**：确认实际开放字段，避免漏掉 OHLC、VWAP、OI；核对复权方式及
  成交量、成交额单位，排除标签和未来信息。
- [ ] **Fold 划分**：固定 Train/Val/Test 日期，同一 fold 内不重叠；预热不计分，
  标签终点不能越过当前 split。
- [ ] **标签与窗口**：明确目标价格、收益公式和预测 Bar 数；确认因子窗口如何跨换约、
  缺口，标签不得跨真实合约或连续段。
- [ ] **Clipping**：固定开关和分位点；如使用 1%–99%，按有效 Train 评分行汇总、
  线性插值，因子和标签独立拟合，标签边界不随因子缺失改变；Train/Val/Test 共用
  冻结边界，NaN/Inf 保持缺失。
- [ ] **指标与方向**：明确 Pearson/Spearman、截面或时序、等权或成交额加权；
  权重样本范围固定，方向只由 Train 决定。
- [ ] **准入与去重**：固定 IC 门槛及严格／非严格不等号、原始有限值覆盖率、相关性阈值、
  最小共同样本数；确认去重是否使用裁剪值。
- [ ] **公平比较**：同组统一快照、字段、fold、算子、参考库、裁剪、诊断和预算；
  记录模型、seed、初始化及上下文重置策略。
- [ ] **组合模型**：单独确认输入和标签是否裁剪；预处理只在训练范围拟合，当前统一使用
  Train+Val；Test 不重新拟合、不选因子、不调参，具体规则见[模型评估](model.md)。
- [ ] **小跑与恢复**：先用 `--search-only` 少量跑 Train/Val，核对指标、准入、日志及断点恢复；续跑保留
  原配置、预算和状态，中途不切换裁剪口径。
- [ ] **冻结与 Test**：正式查看 Test 前冻结研究决策、因子、方向和裁剪边界；
  报告核对单因子、组合模型和 Val 全库因子相似度，注明实际样本数与覆盖率。

## 数据与算子版本

`configs/versions/<name>.json` 是一个可审查的实验配置快照。`atlas versions` 列出版本，
`atlas versions <name>` 展示完整配置。`atlas run --version <name> --method <method>`
复用普通 runner、SearchSession、准入、恢复、冻结和模型评估，不增加另一套研究权限。

版本固定数据适配器及每个源的 MarketData snapshot、允许字段、规范算子语义版本、
asset profile、fold、benchmark 规则、方法配置、算子运行限额和模型参数。
算子注册仍走现有验证和冻结流程；版本目录只控制初始可用的 builtin 集合。
run.json 保存完整版本内容，复用既有配置指纹；数据适配器复用既有 snapshot，
因子沿用规范 AST 与算子依赖身份，不新增来源源码哈希校验或额外账本。
版本名与配置仅在平台内部保存，不进入方法 context。

| 版本 | 特征与算子 | 数据 |
| --- | --- | --- |
| `rq8_fold2_v1` | 原八字段，60 个规范算子 | 原 Kernel 5m 快照 |
| `rq8_zk26_fold2_v2` | 八字段 + 26 项上月发布特征，66 个规范算子 | 原 Kernel + 原生 5m 曲线快照，经月频配方整合 |
| `rq8_zk26_fold2_luna_v3` | 与 v2 相同；所有 LLM 搜索统一 Chat 后端，默认 300 次尝试 | 与 v2 相同快照和配方 |
| `rq8_zk26_seeded_fold2_luna_v4` | 与 v3 相同；全部 B26 作为 26 个初始因子库成员 | 与 v3 相同快照和配方 |
| `rq8_zk26_seeded_fold2_overview_luna_v5` | B26 增量实验；AlphaAtlas `v1_async` 与 AlphaSchema 对齐实验总览的 Luna 方法配置，LightGBM 使用 leaf2000/depth5 | 与 v4 相同快照和配方 |

这些版本使用 fold2（train 2019–2021、val 2022–2023、test 2024–2025），目标为原 5m 行上
未来 12 根 `adj_close` 对数收益。v2、v3 的月频准备使用全部可用历史，普通 5m 搜索窗口
仍只使用 train 前一年的预热。月频计算经过完整日历窗口后才有值；不能把月频预热
解释为所有 5m 表达式都获得了全部历史。

月频配方把 daily DSL、自然月归约及 26 项 monthly DSL 分开记录。`factors_v2.jsonl`
的 `expression` 是可执行月频公式，`published_expression` 才是 5m 方法接口。
曲线输入仅在月频准备层和八字段数据结合；本版不声称把原生远月 5m 行拼成新的原始行情表。
原 `zookeeper_rq_monthly_v1` 的计算口径和历史 baseline 产物保持不变，新路径不覆盖旧结果。

同版本运行不随根目录可变 TOML 改动而变化；修改版本文件或配方后，恢复、OOS 和模型
入口拒绝继续旧运行。新增字段、算子语义、数据快照、配方或研究规则须另存新版本。
`--asset/--fold/--universe/--fields` 与版本冲突时拒绝执行；数据完整性策略按源固定。
seed 和尝试预算仍可显式指定，并记录在运行身份与配置中，比较时必须匹配。

版本可通过 `initial_library` 固定初始库的来源、候选定义和既有因子身份，不导入绩效值。
平台在当前版本的 Train/Val 上测量这些定义，保存方向、裁剪及诊断后，直接建立初始成员。
初始库由实验预先指定，不重新按新发现的准入门槛筛选，也不声称这批成员全部通过当前门槛。
测量条数和耗时单列，不消耗后续搜索尝试；方法实际提交的任何候选仍照常扣预算。

初始成员进入同一个 FactorLibrary：原有查询可读到它们，表达式身份去重及 Val Spearman
查重同时覆盖初始和新增成员。原始 B26 内部的相关性不触发删除；门槛约束后续候选。
定义之外的报告只由当前 Train/Val 生成，Test 不进入初始化或查询。初始成员和测量报告保存
在原有 run.json，恢复及冻结继续使用既有配置指纹、成员恢复和原子 trial，不另建账本。
报告区分初始、新增及总成员；配对增量装配只将新增成员计入 L(m,k)。

无参数覆盖时，选择版本和方法即可执行搜索→冻结→单因子与 Linear/LightGBM OOS。
批量比较使用 `--search-only`，同组开发决定全部冻结后再 `atlas finish <run_dir>`。
仅复跑已冻结结果可以直接 finish；需要重搜时用相同版本、方法、seed 和预算新建 run。
应配合相同 Git 提交和 `uv.lock` 复现实现环境；来源指纹仅记录证据，不保证在线 LLM
服务重复调用产生相同文本。重放已有冻结因子与模型无需再次调用 LLM。

以上版本保留历史 Kernel 1m 聚合 5m 例外，不能称为原生 5m；全部 vintage PIT 证据仍不足。
曲线的两根缺失辅助 Bar 显式保留，test 已经被查看，应称历史诊断留出集。
授权行情不上传 GitHub，其他机器必须自行拥有相同本地快照；不匹配时明确失败，不自动采集。

## 实验流程

1. 固定资产／数据快照、universe、fold、允许字段、方法与 seed、预算、参考库及模型配置。
2. 检查 manifest 与 audit，记录已知例外；修改数据请求使用新快照目录。
3. 运行 train/val 搜索，记录全部尝试、拒绝和成本；需要时沿原检查点恢复。
4. 冻结同组全部开发决策与因子库，单独执行 OOS，不按 test 再选因子或调参。
5. 按相同条件报告全部运行；结果写入[实验记录](records/experiments.md)，列出配置与产物 ID。

### 自动评估与填表

`atlas run` 和 `atlas resume` 在搜索冻结后默认调用完整收尾流程：
Train+Val 拟合并保存 Linear、LightGBM → 单因子 Test → 保存模型的 Test → Val 全库相似度 → 填表。
模型保存后才加载 Test；搜索方法此时已经关闭，Test 和相似度结果不回传方法。
Python 调用在 `runner.run`／`runner.resume` 返回后使用
`experiment.finish_experiment(root, directory)` 完成同一流程。

尝试预算是上限。V1／V1 Async 在全图研究仍无法提出可执行方向时，可正常提前结束并冻结，
以 `search_stop_reason` 记录原因；报告与表格沿用实际提交数，不补齐或伪造预算消耗。
提前结束原因是运行结果元数据，不参与研究配置指纹；配置、因子与算子身份的冻结校验仍有效。
这类结果须披露未耗满预算，不等同于平台证明搜索空间已穷尽。技术和格式错误仍按失败报告。

正式批量比较通过 `--search-only` 先冻结各运行，研究决策全部固定后再执行
`atlas finish <run_dir>`。该命令也用于补跑中断的收尾；已冻结运行上的 `atlas resume`
默认直接继续收尾，不重新搜索。既有配置、数据快照、冻结库、因子身份和运行环境校验保留，
旧运行仍须匹配其保存的研究配置，不按当前默认值改变旧运行的裁剪策略。

单因子沿用冻结训练方向和裁剪边界。Val 相似度沿用实际 profile 的 panel，因子值使用
相同冻结裁剪边界；每对仅在共同有限行上重新排名，配对等权、不抽样、不使用成交额权重。
全部无序不同因子对都必须有效；少于两个成员时没有配对，统计为未定义。
结果原子保存在运行目录的 `library_similarity.json`，包括完整配对和汇总统计。
组合模型保持[模型评估](model.md)的独立预处理口径，不把单因子评分裁剪隐式套到模型输入。

只有单因子、两个组合模型与全库相似度全部完成，才一起更新 `experiment_overview.md`
对应 fold 的结果表和相似度表，并移除该 fold 对应的待开展条目。运行报告链接标识唯一行，
重复执行更新原行；保留人工说明及已知实验人，不用方法名或 seed 覆盖另一独立运行。
报告链接按工作区和运行目录的真实路径计算，允许运行目录通过符号链接位于工作区外；
同一运行的真实路径与符号链接入口复用同一表格行，收尾重试仍复用已完成评估。
同一张表的数据或 Fold／seed 完全一致时，可将对应列提到表前的
`**数据设置**：数据描述。`、`**Fold / seed**：fold2 / 42。`。相似度表的名称也可省略
已统一注明的 Fold／seed。自动填表沿用该布局并核对共同设置；混合设置仍逐行标注。
正式实验总表保留预定预算节点的完整评估结果；中途按入库数量截取的阶段对照保留在
独立比较目录，不汇入正式总表。
任一步失败均不写入半套表格；冻结搜索和已完成评估保留，重试复用完成阶段，
不重复拟合已保存模型，不新增搜索 trial，也不调用模型服务。
空库记录零成员和未定义指标，组合模型不适用，不补造模型或零分。

`atlas compare` 生成跨运行汇总，不会自动证明实验条件可比。组合预测见[模型评估](model.md)：
当前模型在搜索冻结后使用 train+val 拟合，test 仍独立；不可将 val 作为其独立验证结果。

### Zookeeper 26 项组合的固定预算增量实验

机器可读设计协议为
[plan.json](../configs/experiments/zk26_incremental_fold2_300_v1/plan.json)，
主轮命令为 [runs.jsonl](../configs/experiments/zk26_incremental_fold2_300_v1/runs.jsonl)，
可选重复轮为
[replication_runs.jsonl](../configs/experiments/zk26_incremental_fold2_300_v1/replication_runs.jsonl)。
每条 JSONL 记录包含版本、方法、seed、尝试上限及 `argv`；它们是执行计划，不是运行状态账本。

问题是：同一搜索预算下，某方法的**全部准入因子**加入既有 26 项后，能增加多少组合预测能力？
记原库为 B，某方法在预算前缀 k 的准入库为 L(m, k)。分别使用 Linear 和 LightGBM 比较
B 与 B + L(m, k)，不按 Test、单因子排名或人工判断筛选新因子。当前比较只包含逐方法
扩充，配置明确关闭并集；已完成的历史并集产物保留，不进入当前方法增益总表。

| 设计项 | 预定口径 |
| --- | --- |
| 主轮 | 11 个现有方法，各 300 次尝试，搜索 seed 42；总上限 3,300 次 |
| 方法分组 | random/gp/mcts/atlas 为有限文法控制；其余 7 项为 LLM 搜索，见方法目录 |
| 主节点 | 300；预定补充节点 200，取同一条 300 次轨迹的已提交 trial 前缀 |
| 可选重复 | 所有方法追加 seed 43、44，各 300 次；增加 6,600 次，总计 9,900 次 |
| 下游模型 | 两模型都报告，模型 seed 固定 42；参数必须与历史 baseline 的保存配置相同 |
| 主指标 | 同样本、同品种权重上的 Δ√成交额加权 Pearson IC；按两个模型分别报告 |
| 补充指标 | 加权 RankIC 增量、加权 MSE 相对下降、品种等权指标、分年和分品种结果 |
| 不确定性 | 固定预测，按年分层、全市场同步重抽 20 个交易日块，共 2,000 次 |

主轮的一次搜索不足以证明方法稳定优胜。若启用重复轮，须在本轮打开 Test 前决定，并完成
全部方法的三个 seed；不能看过 Test 后只重复赢家。前缀 200 体现预算为 300 时的搜索轨迹，
不是独立设定预算 200 后的算法运行；退火等依赖总预算的策略可能不同。

比较版本 `rq8_zk26_fold2_luna_v3` 沿用 v2 的数据、34 个字段、66 个规范算子及准入规则。
所有 LLM 方法使用同一 `gpt-6-luna` Chat 配置及超时；旧 v2 中混用的模型配置保持不变。
方法自身的温度、修复、对话和并发配置保留；AlphaProbe 的 embedding 另计成本。
这是相同平台条件下的系统比较，不能宣称等 token、等时间或只隔离搜索机制。
真实启动前还须确认同一路由的实际后端和工具调用兼容性；本设计未访问服务或凭据。

各方法从独立空库开始，26 项作为公共特征开放，公共 `futures_cta` 参考定义也一致。
搜索继续使用原单因子准入和奖励，不把组合增量偷偷加入反馈。重复、非法、计算失败、缓存
命中等实际提交照常扣预算；查询、修复及 embedding 的实际模型成本单列。正常早停仍评价
其冻结全库，注明分配上限、实际消耗和未达到的节点；技术失败保留并沿原运行恢复。

上述独立空库条件属于 v3 原设计。用户指定 B26 初始库后的协议为
[seeded plan.json](../configs/experiments/zk26_seeded_fold2_300_v2/plan.json)，使用 v4，
其当前三方法范围见
[three_methods.json](../configs/experiments/zk26_seeded_fold2_300_v2/three_methods.json)。
三方法各 300 次新候选尝试、seed 42，公共查重覆盖 B26 和本轮新增成员；其余配对样本、
模型和重采样口径相同。旧空库运行保留，不续写为新初始条件，也不混入本次主比较。

当前统一模型重训入口为
[单方法 v5 配置](../configs/experiments/zk26_single_methods_v5_20261103/README.md)。
所有来源保持冻结成员、方向和原搜索版本，使用相同 v5 下游模型重训；各 scope 显式关闭
并集。原模型产物保留，当前总表只比较各独立方法对 B26 的增益。

配对拟合先固定 Train+Val 中原 B 的保留列至少一个有限、目标有效且 eligible 的行。
所有方法和 B 使用同一训练 row_id 集合、模型超参及预处理规则；新因子部分缺失沿用训练
均值填补，不要求所有因子完整。Test 主比较固定为 B 可预测且目标有效的行，不把扩充库
新增覆盖混入增量。预测误差使用原始目标；品种去均值模型的校准影响须与 IC 分开解释。
两组 IC 使用共同有效品种；横向排名再列所有可评分方法共同有效品种的结果及损失覆盖。
不能直接拿新结果减去历史归档 IC，因为历史拟合样本可能不同。

成员顺序固定为 B 在先，再按计划中的方法顺序和各自准入 trial 顺序；只按公共因子身份
去掉完全重复定义，并保留来源映射，不按相关性再删列。原训练预处理仍可移除全缺失或常量
列，须区分入库数、去重数和最终可用列数。空库或只重复 B 时，扩充预测复用 B，组合增量
为零；空库自身 IC 仍未定义。普通技术失败不能记成零增量。

ΔIC = IC(B + L) − IC(B)；误差下降 = 1 − MSE(B + L) / MSE(B)。MSE 先按品种平均，
再按完整 Test 的固定 √成交额权重聚合，不平均各品种的下降百分比。区块重采样同时作用
于两组预测，用品种×交易日充分统计量重算 pooled Pearson 和 MSE，不把平均日 IC 当作
全期 IC，也不在每次重采样时重训模型。区间只描述冻结模型的时间波动，不代替 seed 重复，
不作为 11×2 次比较后的显著赢家声明。

执行顺序为：全部 `--search-only` → 冻结全组及前缀成员 → 共同 Train+Val 拟合并保存全部
模型 → 统一评估历史 Test。命令示例：

```bash
uv run atlas run --version rq8_zk26_fold2_luna_v3 --method v1 --seed 42 --attempts 300 --search-only
```

搜索命令复用现有 runner；配对增量入口为 `scripts/evaluate_incremental.py`，使用及产物见
[配对模型评估](model.md#固定-baseline-的配对增量实验)。普通 `atlas model` 和 `atlas finish`
评价的是单个冻结库，不能冒充 B 与 B+L 的比较。配对入口复用 `model.py` 的特征、拟合、
预测及 `evaluation.py` 的指标；合成数据覆盖行对齐、空库／重复、恒定预测、缺失、前缀和
Test 隔离，不另建搜索工具、检查点或预算系统。
配对结果独立保存到 `artifacts/comparisons/`；逐行派生 `.parq` 留在 Git 排除的 `data/`。
不覆盖历史 baseline 或普通运行 `model/`。未来的真实结果写入实验记录，本节只规定设计。

2024–2025 已被查看，结论标为历史诊断留出集增量。未查看的后续期间可以另行预注册作确认，
不能把本轮重新命名为盲测；数据 PIT 和 Kernel 5m 例外沿用上文版本说明。

## 恢复与产物

`artifacts/runs/<run_id>/` 保存运行配置、原子 trial、方法检查点与冻结库；阅读入口是
`report.md`，样本外结果为 `oos.json`。命令见 [README](../README.md#主入口与最小运行)。

恢复沿用原运行和预算，复用已提交反馈，缺失缓存按需重建；配置、数据和冻结校验继续有效。
重建成员时，IC 值按相对容差 `1e-12`、绝对容差 `1e-15` 校验，允许浮点聚合的末位舍入差异；
指标名称、split、聚合口径、样本数、组数、方向、覆盖率和裁剪边界仍须完全一致。
原子 trial 和已入库报告保留原值，重建只恢复所需因子值，不重新准入或扣预算。
源码指纹只作来源记录，不阻止续跑、OOS 或保存模型复用。不增加检查点／缓存哈希或强制重算。
旧产物保留；无检查点的旧运行和任意 `run(session)` 控制流不承诺恢复。
方法状态与模型阶段的保存要求见[方法复现规范](method_reproduction.md#预算失败与恢复)。
