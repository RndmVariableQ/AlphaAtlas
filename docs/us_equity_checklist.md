# 美股数据接入检查清单

目标是让美股数据经过现有 `MarketData`、搜索、准入、冻结与评估链路；具体研究口径以新实验配置为准。
本文是接入验收清单，不替代[研究协议](research_protocol.md)和[方法复现规范](method_reproduction.md)。
状态按当前代码与本地演示材料静态核对，未开展美股真实数据审计或实验。

## 当前确认

- **尚未接入正式美股资产**：`configs/assets/` 中没有美股 profile，`scripts/acquire_data.py` 只支持 A 股与期货。
- **已有合成数据样本**：本地 `data/us_stock/` 的团队 Demo 为 4,000 个证券、5 个交易日、20,000 行、158 列；
  它没有真实 PIT 发布时间、修订史和逐日可投资股票池，不能证明无前视或用于正式研究。
- **平台可复用，但不能只加配置**：已有 Parquet `MarketData`、日度截面 IC、DSL、准入、冻结与单运行 OOS；
  身份、时点、特征、指标和测试仍须按美股验证。现有配对增量评估依赖期货 `product` 与权重，不可直接套用。
- **Demo 时间长度不足**：现有 `build_targets` 使用未来 N 根 Bar；5 个交易日无法产生完整的 5 日前瞻目标，
  更不足以验证普通 fold、预热与滚动窗口。需额外构造较长的合成序列。

## 1. 研究范围与数据交付

- [ ] 确定日线或分钟线、证券范围、历史区间、币种与供应商；明确数据许可、可共享范围和更新频率。
- [ ] 与数据提供方确认原始行情、公司行为、退市／停牌、逐日股票池、财报及历史修订的可用性。
- [ ] 给每个字段记录来源、单位、含义、可见时点、缺失原因及版本；区分行情、特征、身份和目标。
- [ ] 用独立数据目录和快照接入；真实 `.parq`、凭据和供应商数据库不进入 Git，也不修改其他工作区的数据。
- [ ] 确定交易信号产生时点、可使用的当日收盘／财报信息，以及后续评价区间；研究指标不等于可执行收益。

## 2. 身份、股票池和交易日

- [ ] 定义稳定证券身份及其历史映射：Demo 的 `permno` 是证券，`gvkey` 是公司，`iid` 是公司下的证券。
  一家公司多证券、换代码、换交易所和退市须有明确口径；不能把公司 ID 直接当证券 ID。
- [ ] 映射平台 `(exchange, instrument_id)` 并验证其稳定性。当前时间序列按这对键分组，换交易所可能切断历史；
  须明确是否调整适配或分组规则，不能虚构交易所或默默合并证券。
- [ ] 确定逐日 PIT 成员资格、上市／退市、停牌及缺失状态，保留历史退出证券；成员之前的数据仅供预热。
- [ ] 构建与数据一致的美股交易日历和本地时区，覆盖夏令时、休市和提前收市；日线与分钟线分别核对 bar 时间。
- [ ] 用合成样本验证主键唯一、身份映射、双重上市／多股类、交易所变更及连续段重置。

## 3. 价格、公司行为和 PIT 特征

- [ ] 明确未复权、拆股复权、现金分红及总收益的用途，验证拆股、分红和退市边界；不能把价格收益默认当总收益。
- [ ] 定义复权因子的可见时点，检查历史调整是否引入未来信息，并记录数据源的历史修订限制。
- [ ] 财务特征保留报告期、公告／生效或可获得时间、版本／修订及来源；按决策时点进行 as-of 连接。
- [ ] 验证盘前、盘中、盘后披露、同日可用性、修订和缺失；有保守延迟时写入配置，未知时点不能冒充 PIT。
- [ ] 明确年度、季度、TTM、滞后及过期规则。Demo 的 `_lag1y` 表示上一财年，并非前一交易日。
- [ ] 按证券／公司层级核对特征。Demo 的公司 `market_cap` 会在同公司多证券行重复，不能直接跨证券行求和。
- [ ] 做前缀不变性测试：只追加未来行情、公告或修订，过去已生成的特征、资格及评估结果不变。

## 4. 适配、字段与质量审计

- [ ] 将数据映射到 `row_id`、`timestamp`、`trading_day`、`exchange`、`instrument_id` 及数值字段；
  保证行 ID 稳定且唯一，标识、成员资格、时间元数据与目标不得作为数值特征。
- [ ] **特别核对 `permno`**：它在 Demo 中是数值列，而当前 `get_fields()` 按数值 schema 发现特征；
  适配时须将其作为身份元数据处理，不能让它进入默认特征或 DSL 字段列表。
- [ ] 明确字段映射及单位转换。Demo 的 `vol` 为百万股、`prcvol` 为百万美元；`open/high/low/close` 为拆股复权价。
  在映射 `volume`、`amount` 及价格字段前核对量纲、取值和是否存在需要补充的原始 OHLC。
- [ ] 逐一核验 Demo 的数值字段，包括 `total_return`，在信号产生时是否已知；不把当日可得性直接推广到盘前或盘中。
- [ ] 定义缺失、异常 OHLC、零成交、停牌和退市处理；保留原始异常证据，不填造价格或未来字段。
- [ ] 产出可复用的分区、`manifest.json`、交易日历和快照身份；验证分区哈希、行数、缺口、唯一键与字段覆盖。
- [ ] 提供完整交易日历：当前适配器缺少日历文件时会回退到数据中观察到的日期，整市场缺失的一天可能无法识别。
- [ ] 扩展或验证现有 `audit` 的美股规则。它当前有 A 股成员字段和财务来源日判断，不能把审计通过直接当作 PIT 认证。
- [ ] 核对目录与入口：当前 `data-status`／`audit-data` 按 `data/<asset>/` 查找；若实际 `data_dir` 不同，须验证入口行为。
- [ ] 如采用现有 Parquet 格式，验证 `ParqMarketData` 的日历、资格、连续段与字段排除逻辑；
  如增加新 adapter，接入 `assets/versioned.py`，不让研究方法直接读供应商或 Parquet。

参考：[资产键与行 ID](../src/alpha_atlas/assets/common.py)、[MarketData 实现](../src/alpha_atlas/assets/market.py)、
[审计](../src/alpha_atlas/assets/audit.py)、[版本数据入口](../src/alpha_atlas/assets/versioned.py)。

## 5. 配置、标签、评价与准入

- [ ] 新建美股 asset profile 和实验版本；固定频率、时区、目标价格、预测 horizon、panel、universe、fold、字段与数据快照。
- [ ] 确认 `panel=contract` 在当前实现中表示按 `(exchange, instrument_id, segment_id)` 分组；对美股逐项验证，不借用期货 `product`。
- [ ] 确认目标收益：当前 `build_targets` 计算同证券同连续段的未来价格对数比，不自动纳入分红或 Demo 的 `total_return`。
  若研究需要总收益或退市收益，先实现并测试明确的标签语义，再生成新版本。
- [ ] 固定 Train／Val／Test、预热、预测周期与标签终点边界；检查上市、退市、停牌和缺口不会跨段或跨 split 泄漏。
- [ ] 选择主指标及加权规则。当前截面主指标仅支持 `cross_sectional_spearman`，并同时报告 Pearson；
  若需要 Pearson 主指标或其他美股加权方式，先实现并验证，不能只修改配置名。
- [ ] 固定方向、覆盖率、IC 门槛、共同样本数、去重、训练期裁剪与残差准入；不要直接把期货门槛当作美股默认结论。
- [ ] 在**新版本**里显式关闭或替换期货专用 `reference_library = "futures_cta"`；确认初始库和参考库的字段权限与所有方法一致。
- [ ] 用独立手算样例核对日期截面相关、方向、裁剪、空值、常量、低覆盖和相同／不同证券的结果。

参考：[目标与指标](../src/alpha_atlas/evaluation.py)、[版本校验](../src/alpha_atlas/versions.py)、
[准入](../src/alpha_atlas/library.py)、[默认规则](../configs/benchmark.toml)。

## 6. 方法、预算和研究工具

- [ ] 先用 Random 和合成数据打通统一 `atlas run`；再逐个验证需要接入的 LLM 方法，不假设所有方法天然兼容美股。
- [ ] 确认 `get_context` 中的频率、字段、标签与指标正确；检查远月合约等期货提示是否需要按资产收敛。
- [ ] 验证模型只接收公共工具和 Train／Val 反馈；日期、fold、universe、运行／快照 ID 与 Test 标签不进入模型提示。
- [ ] 审查方法的 Python 实现是否绕过数据边界；当前 `SearchSession` 是接口约定，不是隔离不可信代码的沙箱。
- [ ] V2／V3 需要 `library_residual` 和共享诊断；在美股合成截面上验证残差数值、准入边界、并发提交与地图状态。
- [ ] 核对方法字段假设、算子、参考库、初始库、模型服务、搜索空间与预算；比较时固定共同条件并记录调用成本。
- [ ] 每个 `(asset, dataset, universe, fold, method, seed, run_id)` 使用独立因子库与地图，避免与期货或 A 股混用。

参考：[研究工具](research_tools.md)、[方法目录](methods/README.md)、[runner](../src/alpha_atlas/runner.py)。

## 7. 冻结、OOS、模型与报告

- [ ] 验证 trial 原子提交、失败扣预算、断点恢复、缓存重建及配置／快照不匹配时拒绝继续。
- [ ] 全部开发决策固定后冻结定义、方向、依赖与训练裁剪边界；Test 不参与搜索、选因子或参数调整。
- [ ] 对固定合成因子库核对独立 OOS、Linear 和 LightGBM 的行对齐、预处理、指标与缺失；模型仅使用 Train+Val 拟合。
- [ ] 普通 `atlas run` / `finish` 走单运行收尾。当前 `atlas experiment` 的配对增量实现使用 `product` 和期货权重；
  美股配对比较须先确定共同样本、权重、基线与不确定性口径，再实现并验证。
- [ ] 报告数据快照、股票池、覆盖、口径与已知限制；确认观测台和日志不假设期货字段，不自动改写实验总表。
- [ ] 在另一份干净 checkout 上用共享的**合成数据**复跑；真实快照和模型服务的交付方式另行约定。

## 8. 合并前验收顺序

1. 与数据提供方确认身份、字段、时点、缺失、股票池与授权；保留 Demo 为合成样本。
2. 用较长的合成日历与事件构造数据，完成适配、PIT／质量审计及负例测试。
3. 冻结美股配置，依次验证 Random、小规模 V3（模拟模型服务）、恢复、冻结及 OOS。
4. 需要跨方法配对比较时，再完成美股专属对齐和指标实现；对期货、A 股运行回归检查。
5. 执行 `pwsh -File scripts/check.ps1`；真实数据采集、模型调用与正式实验另行显式发起。

交付至少包含：适配与字段说明、合成测试、数据 manifest／审计口径、实验配置、已知限制和复现命令。
